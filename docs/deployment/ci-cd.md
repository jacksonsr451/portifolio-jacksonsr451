# CI/CD

`.github/workflows/ci.yml` checks PRs and `main` pushes on PHP 8.4 and 8.5; update branch filters if another default branch is selected. Require both `quality (8.4)` and `quality (8.5)` status checks (Pint, Larastan, Pest with ≥80% scoped coverage, Vite build). `security.yml` audits dependencies and runs CodeQL for JavaScript/Actions (PHP is not a supported CodeQL language), plus secret scanning and PR dependency review. Private-repository feature availability depends on the GitHub plan and settings. `deploy.yml` accepts only a full commit SHA reachable from the default branch and reruns quality/audit checks; it remains gated on explicit target settings, `DEPLOYMENT_ENABLED`, a protected SSH key and pinned known-hosts secret, and the reviewed `vps-ssh.sh` adapter. The adapter keeps release volumes external and performs checksum, lock, migration backup, health, smoke, and rollback checks. `release.yml` is manual, validates semver tags and their checked-out commit, reruns quality/audit checks, and creates a draft release.

Repository administrators should protect the default branch, require both PHP matrix checks (`quality (8.4)` and `quality (8.5)`) and appropriate security checks, require review (at least one when collaborators are available), disallow direct pushes, and choose squash merge. Review Dependabot PRs like code: inspect changelog/advisory, lockfile diff, and CI before merging. Configure GitHub secret scanning/push protection when available. These settings require repository-owner authorization and are not applied by workflow files. Keep a private repository until portfolio content and links are approved for public disclosure.
