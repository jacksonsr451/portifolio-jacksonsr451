# CI/CD

`.github/workflows/ci.yml` checks PRs and `main` pushes; update the branch filters if another default branch is selected. Required checks are the `quality` job (Pint, Larastan, Pest, Vite build). `security.yml` audits dependencies and runs CodeQL for JavaScript/Actions (PHP is not a supported CodeQL language), plus secret scanning and PR dependency review. Private-repository feature availability depends on the GitHub plan and settings. `deploy.yml` deliberately exits before deployment unless explicit target settings, a protected credential, and an adapter entrypoint are supplied; no provider or host is invented. `release.yml` is manual, validates a tagged revision, and creates a draft release after checks.

Repository administrators should protect the default branch, require `quality` and appropriate security checks, require review (at least one when collaborators are available), disallow direct pushes, and choose squash merge. Review Dependabot PRs like code: inspect changelog/advisory, lockfile diff, and CI before merging. Configure GitHub secret scanning/push protection when available. These settings require repository-owner authorization and are not applied by workflow files. Keep a private repository until portfolio content and links are approved for public disclosure.
