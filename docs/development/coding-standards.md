# Coding standards

Follow Laravel naming, routing, validation, and Blade conventions. Prefer direct framework features over bespoke layers. Keep controllers focused and content readable. Use semantic HTML, keyboard-accessible controls, escaped Blade interpolation, and URL-encoded links. Run Pint (`composer lint`), Larastan (`composer analyse`), Pest (`composer test`), and `npm run build` before review. Avoid unneeded packages and test internals only where they protect meaningful behavior.
